# AstroHopper for iOS

A native SwiftUI port of the AstroHopper web app for iPhone (iOS 27).

## Building

Requirements: Xcode 27, Python 3, and the repository's git submodules:

```sh
git submodule update --init
open ios/AstroHopper.xcodeproj
```

Before running on a device, set your development team and change the bundle ID (`com.example.AstroHopper`) in `project.yml`, or in the target's Signing settings.

A pre-build script runs `Tools/generate_data.py`. It writes `AstroHopper/Generated/catalog.json` (the same star, DSO and constellation selection as the web app's `jsdb.js`) and `vsop87a.json` (the planet series from `vsop87a_combined.js`). Both files are gitignored.

The project file is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`. Run `xcodegen generate` in `ios/` after adding or removing source files.

Tests:

```sh
xcodebuild -project ios/AstroHopper.xcodeproj -scheme AstroHopper \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' test
```

In the simulator, or on any device without a gyroscope, the app runs in demo mode: dragging moves a virtual telescope.

## Differences from the web app

- **Sensors:** the app uses Core Motion's fused attitude in the true-north frame. Tilt comes from gravity, the absolute yaw replaces `webkitCompassHeading`, and a gyro-only yaw is integrated separately for tracking after alignment, so magnetic disturbances can't move an aligned map. Before alignment, the compass yaw uses true north instead of magnetic north.
- **Screen:** the UI is locked to portrait so it doesn't rotate while the phone is on the tube, the screen doesn't auto-lock, and pinch zoom is on by default. There is no full-screen option, since the app is always full screen.
- **Manual:** the in-app manual is `AstroHopper/Resources/Help.md`, an iOS version of the top-level `README.md`.
- **Location:** the last known location is remembered between launches.
- **User object parsing:** two bugs from the web version are fixed. Dec seconds were read from the minutes field, and a Unicode minus `−` produced NaN.
