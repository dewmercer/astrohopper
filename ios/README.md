# AstroHopper for iOS

A native SwiftUI port of the AstroHopper web app for iPhone (iOS 27).

## Building

Requirements: Xcode 27, Python 3, and the repository's git submodules:

```sh
git submodule update --init
open ios/AstroHopper.xcodeproj
```

Before running on a device, set your development team and change the bundle ID (`com.example.AstroHopper`) in `project.yml`, or in the target's Signing settings.

A pre-build script runs `Tools/generate_data.py`. It writes `AstroHopper/Generated/catalog.json` (the same star, DSO and constellation selection as the web app's `jsdb.js`) and `vsop87a.json` (the planet series from `vsop87a_combined.js`). Both files are gitignored.

The project file is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`. Run `xcodegen generate` in `ios/` after adding or removing source files.

Tests:

```sh
xcodebuild -project ios/AstroHopper.xcodeproj -scheme AstroHopper \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' test
```

In the simulator, or on any device without a gyroscope, the app runs in demo mode: dragging moves a virtual telescope.

## Differences from the web app

- **Sensors:** the app uses Core Motion's fused attitude in the true-north frame. Tilt comes from gravity, the absolute yaw replaces `webkitCompassHeading`, and a gyro-only yaw is integrated separately for tracking after alignment, so magnetic disturbances can't move an aligned map. Before alignment, the compass yaw uses true north instead of magnetic north.
- **Interface:** a native iOS design instead of the web page's controls. There's a Liquid Glass toolbar (Align, Search, Lists, Compass, Settings), a status capsule, and a target card showing how far to move. Search shows a list of results, Settings is a grouped form with separate editor screens, and the quick start is a swipeable sheet shown on first launch. Night mode swaps in red versions of controls that would otherwise draw white. The Small UI and full-screen options are gone; the layout adapts on its own.
- **Alignment:** instead of a 3 s countdown, the user taps **Aligned** once the star is centered. The attitude from 0.25 s before the finger touched the button is used, so the tap's shake doesn't count. Optional 2- and 3-star alignment (`Model/Alignment.swift`) fits the azimuth offset, the phone's mounting offset from the tube axis and, with 3 stars, a small tilt, by least squares; the app suggests each next star. One-star alignment is the web app's `selectAlign()`.
- **Field of view circles:** optional finder and eyepiece circles, with a haptic tap when the target enters each.
- **Telescope control:** optional goto for Celestron mounts through a SkyPortal WiFi module (`Model/AUX*.swift`, `Mount.swift`, `TelescopeController.swift`). The module bridges the AUX motor bus to TCP port 2000, at 1.2.3.4 in direct mode. The protocol follows the INDI `celestronaux` driver. AstroHopper aligns the mount itself: each confirmed alignment star also records the encoder angles, and the same pointing fit runs in the mount's frame (the celestial pole is "up" for equatorial mounts), detecting the axis directions from 2+ stars. Goto runs fast then slow, then tracks by setting each axis's guide rate. Tests drive a fake module over loopback TCP. Connecting needs the Local Network permission. This is the only network use besides the user-opened Wikipedia pages.
- **Screen:** the UI is locked to portrait so it doesn't rotate while the phone is on the tube, the screen doesn't auto-lock, and pinch zoom is on by default.
- **Manual:** the in-app manual is `AstroHopper/Resources/Help.md`, an iOS version of the top-level `README.md`.
- **Location:** the last known location is remembered between launches.
- **User object parsing:** two bugs from the web version are fixed. Dec seconds were read from the minutes field, and a Unicode minus `−` produced NaN.
